Iron Man 3D Portfolio: Complete Project Info

How the portfolio works from scratch: the concept, the architecture, how a plain GLB file becomes a scripted, animated "action model", and how the scroll, camera, effects and page content fit together. All details are taken from the source code in this repository.

01The idea

The site is a normal portfolio (Hero, About, Experience, Skills, Projects, Achievements, Contact) laid over one fixed, page-wide 3D canvas. That canvas shows a single Iron Man suit. As the visitor scrolls, the suit behaves like an actor following a script.

Page positionWhat the suit does
HeroHelmet close-up, eyes and reactor power up, camera pulls back to full body on the right.
AboutFlight: lifts off, sweeps across the page, exits the left edge and re-enters from the right.
ExperienceLands beside the text and fires its repulsors.
Skills to AchievementsOff-stage, so dense content gets the whole screen.
ContactReturns and runs a holographic scan sweep.
Content never depends on 3D. A WebP poster of the same model paints first (it is the LCP element). It remains the fallback when WebGL is unavailable, the GL context is lost, or the visitor prefers reduced motion.

04Architecture

Three actors share one plain object, bus (src/three/bus.ts): the DOM (scroll, buttons, pointer, GSAP), the scroll director, and the R3F scene. Because the bus is mutable and not React state, per-frame values never trigger re-renders. React state is used only for slow things: scene status, hero phase and the action label.

05From a normal GLB to an action model

Key fact: the supplied GLB has no usable animation. It contains 3 clips, all T-pose, and nothing for fire, flight or scan. All motion is authored in code on top of the model's skeleton.

Step 1: inspect the original

  • One skinned mesh Iron_Man_mark_7_Subsurf_, about 137k vertices and 143k triangles.
  • One PBR material: base colour, normal, metal-rough and a baked emissive texture (visor and reactor are already painted in), four 4096² PNGs.
  • The mesh is skinned only to the iron man_Rigify armature (DEF-* bones). Two other armatures (CC rig, metarig) and IK helper nodes are unused.
  • Three animation clips, all T-Pose.

Step 2: optimise (scripts/optimize-model.mjs)

Built with glTF-Transform. It produces two files from model-source/ironman.original.glb:

OutputTexture sizeWebP quality
public/models/ironman.glb204882
public/models/ironman-lite.glb102478
  1. Dispose all animations (all T-pose, unused).
  2. Dispose every scene root except the iron man_Rigify node (drops the unused rigs).
  3. prune, dedup, textureCompress (WebP, resized).
  4. quantize (position 14, normal 10, texcoord 14 bits) and meshopt compression (medium).

Materials and textures are otherwise untouched. Because meshopt is used, the loader is called as useGLTF(url, false, true) (Draco off, meshopt on).

Step 3: load and isolate (Armor.tsx)

clone(scene) from SkeletonUtils creates an independent skeleton and skinned mesh, then updateMatrixWorld(true) captures the bind pose. Skinned meshes get frustumCulled = false (skinned bounds can lag behind the pose). Textures keep their original materials; only anisotropy is raised to 8. The original emissiveIntensity of each material is stored in userData.baseEI so the power-up can scale it later.

Step 4: fit to the stage

box    = Box3.setFromObject(model)
scale  = SUIT_HEIGHT (3.4) / box.size.y
offset = (-centre.x*scale, -box.min.y*scale, -centre.z*scale)   // feet on y=0, centred

The model sits in nested groups, outermost first: lift (hover and recoil), lean (pivot at the hip, HIP_Y = 1.75; body pitch, yaw, bank), then the offset/scale group holding the model.

Step 5: anchor effects to real bones (anchors.ts)

Effect positions were measured on the real geometry (ray-casts on the skinned mesh and bone world positions), in model space at bind pose:

AnchorBonePoint (model space)Normal
chest (arc reactor)DEF-spine003(0, 3.81, 0.451)(-0.05, 0.32, 0.95)
palmLDEF-handL(0.905, 2.57, 0.045)(-0.98, -0.17, -0.06)
palmRDEF-handR(-0.905, 2.57, 0.045)(0.98, -0.17, -0.06)
eyeL / eyeRDEF-spine006 (head)(±0.1, 4.545, 0.347)(±0.12, 0, 0.99)
soleL / soleRfoot bones(±0.428, 0.03, 0.12)(0, -1, 0)

createAnchor(root, bone, point, normal, lift) must run while the model is still in bind pose and untransformed. It:

  1. Moves the point out along the normal by lift (avoids z-fighting with the surface).
  2. Converts it to bone-local space with inverse(bone.matrixWorld).
  3. Rotates the anchor so local +Z equals the surface normal.
  4. Cancels the bone's world scale, so effects are authored in plain model units.
  5. bone.add(anchor): the anchor is now a child of the bone.

React then renders effects into those anchors with createPortal(<ChestReactor/>, anchors.chest) (same for repulsors and thrusters). Since an anchor is a child of a bone, the glow moves with the skeleton and never floats independently.

Step 6: build the posing rig

BONE_NODES in actions.ts maps 20 logical joints (pelvis, spine1/2, chest, neck, head, shoulders, upper arms, forearms, hands, thighs, shins, feet) to Rigify bone names. For each, poseBone() stores the bone, its rest quaternion, and its parent's world quaternion (and the inverse) at bind. The core of the whole system is drive():

bone.quaternion = parentInv * delta * parent * rest
// delta = Euler(pitch, yaw, roll, order 'YXZ') in MODEL-SPACE axes

This expresses every pose as a rotation in model-space axes layered on top of the bind rotation. Rigify bone-local axes are arbitrary; this lets poses be authored intuitively (the suit faces +Z, arms hang down -Y; arm pitch < 0 swings forward, > 0 back; left-arm roll > 0 lifts outward).

Step 7: author the actions (actions.ts)

POSES

Joint deltas as [pitch, yaw, roll] radians per bone: fireL, fireR, flight, scan.

  • limbs('L'|'R', set) writes the left side once and mirrors for the right (pitch shared; yaw and roll flip).
  • merge() sums poses.
  • AIM: arm raised about 65° and angled outward, wrist extended, hand rolled about 90° so the palm repulsor faces down the arm.

TIMELINES

sampleAction(name, t, frame, hold) fills an ActionFrame of target weights (armL, armR, beamL, beamR, flight, scan, scanP, scanA, recoil) from envelope helpers:

  • sstep: smoothstep.
  • pulse(t, a, b, rin, rout): rise, hold, fall.
  • kick(t, at, rate): exponentially decaying impulse (recoil).
ActionDurationSequence
fire3.6 sRight arm up 0–2.1 s, left arm 1.0–3.1 s. Beams at 0.5 s (R) and 1.5 s (L), each with a recoil kick. Torso twists toward the aiming side.
flight5.2 sArms sweep back, legs trail, head tilts up, body leans forward and lifts. Thrusters ignite.
scan3.8 sArms open, head sweeps left and right while scanP (0.35–3.0 s) drives a ring up the body; scanA controls its visibility.

With hold = true (used when the scroll director owns the action) fire and scan loop via t % DURATION, and flight stays engaged. ignite(t) is the power-up curve: dark, then flicker, then fully lit.

Step 8: the per-frame loop (useFrame in Armor)

  1. Power-up. Once bus.reveal > 0.55, powerT counts up and ignite() sets bus.power. Each material's emissiveIntensity = baseEI * (0.04 + 0.96 * power), which lights the baked visor and reactor.
  2. State machine. A visitor action in bus.pending wins (start or 'stop'). Otherwise, if idle or already in a held action, the suit follows bus.mode from the director.
  3. Sample. Advance sim.t, call sampleAction. A non-held action stops itself at DURATION.
  4. Smooth. MathUtils.damp eases each weight (arms 9, flight 4, scan 5, recoil 30). Under reduced motion the rate is multiplied by 1000, so it is effectively instant.
  5. Mix. Zero a per-bone scratch sum, add idle life (breathing, weight shift, arm sway, glances, scaled by calm, which drops as actions engage), then addPose(POSES.x, weight) for each pose, recoil, and head/neck pointer tracking plus the scan look.
  6. Drive. drive(rig[key], pitch, yaw, roll) for every bone. This is where the pose reaches the skeleton and the skinned mesh deforms.
  7. Whole body. Hover, lift, forward lean, yaw (shot plus drag plus arm-difference twist), bank. The world quaternion is saved to bus.rootQ.
  8. Publish. Write bus.fx (beamL/R, thrust, lift, scanP/A, reactor). The FX components only read these values, so the skeleton and the effects stay in sync with no events between them.

No React state and no per-frame allocations are used in this loop; scratch quaternions and arrays are reused.

06Scroll director and camera

director.ts

build() measures the actual positions of #home, #about, #experience, #skills, #contact and builds an array of keyframes { y, mode, dist, look, fx, fy, yaw, pitch, bank, alpha, floor }. It rebuilds on resize, on a ResizeObserver of the body, and once more 1.2 s after load, so it survives any content height or viewport size. Distances are computed from the 30° field of view so the suit takes the same share of the viewport at any aspect ratio.

apply() runs on a rAF-throttled scroll event: it finds the surrounding keys, lerps all numeric fields (distance logarithmically), writes bus.shot and bus.mode, sets the --hero-p CSS variable and publishes the hero phase.

Hero phaseMeaning
0Face and name (helmet close-up).
1Camera starts to pull back; main copy fades in.
2Full body on the right; drag/click interaction enabled.
3Past the hero.

WIDE VS NARROW

Wide = width ≥ 900 and aspect > 1.15. Narrow layouts centre the suit, pull it further back and dim it (alpha 0.28 beside text).

FLIGHT TRICK

The suit exits left, then a 2 px jump in keys brings it in from the right. The Rig snaps view.fx when the jump exceeds 1.0 instead of sliding across the screen.

STANDING SPOT

Next to a section with a [data-gutter] column, the suit's x shift is computed from that column's right edge so it never covers the copy.

Camera rig (Stage.tsx → Rig)

  • Eases bus.view toward bus.shot with damp (smooths scroll jitter).
  • Camera sits at (0, look, dist) looking at (0, look, 0).
  • Uses camera.setViewOffset to shift the suit sideways/vertically on screen without moving the camera off-axis.
  • Writes the canvas layer's CSS opacity from view.alpha.
  • When fully faded out (and not returning) for 0.35 s it calls setVisible(false); the canvas frameloop becomes 'never' and nothing renders until the director wakes it.

Lighting and environment

  • Warm key spotlight, red and blue rim directionals, hemisphere fill; all intensities multiplied by bus.reveal.
  • Procedural studio reflections via Environment + Lightformer (no HDR download), rendered once (frames={1}).
  • ACES filmic tone mapping, exposure 1.05, transparent canvas.
  • Atmosphere: additive volumetric spotlight cone (fresnel-style shader) and two floor rings.
  • ContactShadows baked once, visible only while grounded.

Each is portalled into a bone anchor (local +Z is the surface normal) and driven purely by bus values.

08Interaction

  • Pointer head tracking. Mouse only (pointerType === 'mouse'); touch keeps native scrolling. Reduced while an action runs, while the body is yawed, and entirely under reduced motion.
  • Drag the invisible .scene-hit area to turn the suit (clamped ±1.6 rad); it springs back on release.
  • Click without dragging (movement < 6 px) calls triggerAction('fire'). Triggering the running action again cancels it.
  • The hit area exists only in hero phase 2 and when the scene is ready.
  • Idle life: breathing, weight shift, arm sway and glances.
  • Sound is procedural (sound.ts, no audio files), off by default, and only plays if the visitor turns it on.

09Intro and boot sequence

  1. If the intro has not been seen this session (session.ts) and reduced motion is off, Intro overlays the already-rendered page.
  2. GSAP is lazy-imported. bus.reveal = 0 (scene dark). The reactor icon fades in, boot lines type out, a progress bar fills, a scan line passes.
  3. At the reveal label the timeline pauses until whenReady(1800) resolves (model parsed, or timeout), so the reveal never plays on an empty stage.
  4. The veil opens, bus.reveal tweens 0 → 1, the power sound plays, "STARK SYSTEMS ONLINE" appears.
  5. Once reveal passes 0.55, Armor starts the ignite() curve: visor and reactor flicker on.
  6. Skip with the button or Esc; the choice is remembered for the session.

10Performance and accessibility

PERFORMANCE

  • 3D chunk is lazy(), mounted after load and browser idle; the poster is the LCP.
  • detectQuality() uses cores, device memory, pointer type, width and save-data. Tiers: high (full GLB, DPR 1–2, 90 sparkles), medium (lite GLB, DPR 1–1.5, 36), low (lite, DPR 1–1.25, no sparkles, no AA).
  • PerformanceMonitor and AdaptiveDpr lower DPR at runtime.
  • Render loop stops when the suit is off-stage or the tab is hidden.
  • Shadows and environment are baked once.
  • GL context loss falls back to the poster.

ACCESSIBILITY

  • Reduced motion: static layout, no intro, no idle motion, no lift/lean, instant damping, no auto scrolling.
  • Canvas is aria-hidden; an sr-only live region announces actions.
  • Skip link, visible focus rings, accessible mobile menu, announced form errors.
  • Custom cursor is decorative, and disabled on touch or reduced motion.
  • Poster has real alt text.

Static site, relative base. Build command npm run build, output directory dist. Works on Vercel, Netlify, Cloudflare Pages, GitHub Pages or any static host. Serve /assets/* and /models/* with long-lived immutable cache headers.
